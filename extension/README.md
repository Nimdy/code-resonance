# Code Resonance — VS Code extension

Start the Code Resonance receiver (`npm start` in the Code Resonance source) on the **same OS or remote host as this extension host** (for example inside WSL for a WSL workspace). In a trusted workspace, click the **CR** status-bar item or run **Code Resonance: Start Code Performance**, and accept local capture. The status-bar menu stops capture and opens the Stage or the OBS view. Capture resumes after a VS Code restart until you stop it.

What leaves the editor: bounded source snapshots for analysis (unless `resonance.captureDocumentContents` is off), per-second edit counts (never typed text), file operations, diagnostics counts, task and terminal command categories with exit codes (command text only if `resonance.captureTerminalCommands` is on), Git commits, and the folder name for the local project list (`resonance.shareProjectName`). Everything goes only to the loopback receiver; the outbox keeps events on disk while the receiver is offline.

What the extension reports about itself (0.5+): when capture starts (`workspace.started`), and again when a `resonance.*` setting changes while capturing (`workspace.settings`, at most one per quiet 500 ms and only if a reported value changed), it sends its version, the remote kind (`vscode.env.remoteName`, for example `wsl` or `ssh-remote`; empty for a local window) and the values of `includeHidden`, `captureDocumentContents`, `captureTerminalCommands`, `capturePromptText`, `shareProjectName`, `baselineFileLimit` and `receiverPort`. Values only: no paths, folder or host names. This lets the Control Center show what this capture actually does instead of assuming defaults; the receiver never writes VS Code settings. `receiverPort` is the port the running capture delivers to: a changed port applies at the next start. The extension does not report VS Code closing, so a capture that started long ago with no activity since is unknown, not live.

`vscode://zerobandwidth.code-resonance/settings` (linked from the Control Center) opens these settings (`@ext:zerobandwidth.code-resonance`) and nothing else: a link cannot start capture or change a setting.

This extension does not execute code, infer hidden model thoughts, send telemetry, or depend on Signal/3.
